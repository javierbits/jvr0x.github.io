# AGENTS.md: how jvr0x.com is built

Static HTML/CSS/JS served by GitHub Pages straight from the `main` branch root (custom
domain in `CNAME`, `.nojekyll` so nothing is processed). **The committed HTML is the served
output.** There is no build on GitHub: run the build locally and commit the result.

## Layout

| Path | What it is |
| --- | --- |
| `index.html`, `<section>/index.html` | Site pages: `/`, `/about/`, `/newsletter/`, `/models/`, `/recipes/`, `/lab/`, `/tools/`, `/bots/` |
| `voxel-bridge-challenge/index.html` | Voxel challenge hub (gets the shared chrome) |
| `voxel-bridge-challenge/<model>/index.html` | Model outputs being compared. **Never add chrome or edit them**; they are the artifacts |
| `voxel-bridge-challenge/qween3.8-flash-next-dual/` | Redirect stub to the renamed `qwen3.8-flash-next-dual/` |
| `partials/header.html`, `partials/footer.html` | Shared header/footer (the CHROME.md contract) |
| `assets/chrome.css` | Styles for every `jx-` class; also loaded by project repos |
| `style.css`, `script.js` | Site styles; fade-in on scroll |
| `assets/models.js` | Models page only: re-renders the card list from the live Hugging Face API, keeping the committed cards as fallback |
| `data/pages.json` | Every page: path, file, title, description (drives head tags, chrome and sitemap) |
| `data/*.json` | Card lists: `home`, `models`, `bots`, `tools`, `lab`, `recipe-forks`, `recipes`, `bench-recipes` |
| `tools/build.py` | The build (stdlib only) |
| `tools/og.py` + `tools/og-template.html` | Renders `assets/og-default.png` (1200x630) |
| `tools/measure_embed.py` | Measures the Substack embed height used in `chrome.css` |
| `tools/check_site.py`, `tools/shots.py` | Verification (see below) |
| `tests/test_build.py` | pytest suite for the build |
| `robots.txt`, `llms.txt`, `sitemap.xml` | Crawler files (`sitemap.xml` is generated) |

`AGENTS.md`, `README.md`, `tools/*.py` and `tests/` are plain files in the repo, not pages.

## Build

```bash
python3 tools/build.py            # offline and idempotent: a second run changes nothing
python3 tools/build.py --recipes  # first refreshes data/recipes.json + data/bench-recipes.json via `gh api`
python3 tools/build.py --models   # first refreshes data/models.json from the Hugging Face API
```

For every page in `data/pages.json` that has a `file`, the build rewrites these marker blocks:

- `<!-- jx:head -->...<!-- /jx:head -->`: `<title>`, meta description, canonical and the full OG/Twitter set, from `pages.json`
- `<!-- jx:header -->...<!-- /jx:header -->` and `<!-- jx:footer -->...<!-- /jx:footer -->`: from `partials/`
- `<!-- jx:cards NAME -->...<!-- /jx:cards -->`: cards from `data/NAME.json` (add ` list` after NAME for compact rows)

It also writes `sitemap.xml` from `pages.json`. Entries without a `file` (`/tok-sim/`,
`/dgx-spark-bench/`, `/murmur/`, `/soldecode-extension/`) are project pages served by their own
repos and only go into the sitemap. Pages are rendered in memory first, so a missing marker or
bad data aborts the build without writing anything.

Card entries: `{"title", "url", "description"?, "meta"?, "tags"?: [str], "links"?: [{"label", "url"}]}`.
URLs must be `https://...`, `http://...` or root-relative `/...`. All text is HTML-escaped.

### Common changes

- **New bot / tool**: add one entry to `data/bots.json` / `data/tools.json`, run the build, commit.
- **New page**: create `<name>/index.html` with the head/header/footer markers (copy any subpage), add it
  to `data/pages.json`, run the build.
- **New project repo page on jvr0x.com**: add `{"path": "/<repo>/"}` to `data/pages.json` and to
  `PROJECT_PREFIXES` in `tools/check_site.py` and `tools/shots.py`.
- **Recipes**: `data/recipes.json` (lmswitch YAMLs at the root of `javierbits/ai-models`) and
  `data/bench-recipes.json` (measured series in `javierbits/dgx-spark-bench/results/*.json`) are generated by
  `--recipes`; don't hand-edit them. A bench config links to an lmswitch YAML only on an exact name match
  (a YAML file inside the bench recipe dir, else the dir name, equals an ai-models file stem).
  Hand-written recipe entries live in `data/recipe-forks.json`.
- **New model on Hugging Face**: nothing to edit. `/models/` reads the live `javierbits` profile, and
  `python3 tools/build.py --models` refreshes the committed cards (crawlable, no-JS baseline) to match.
  Card copy is derived from the repo tags; to write your own for a release, keep its `hf` key in
  `data/models.json` and hand-edit `title`/`description`/`meta`/`tags`/`links` (empty fields fall back to derived ones).

## Shared chrome contract (project repos)

Project pages on the same domain (tok-sim, dgx-spark-bench, murmur, soldecode-extension) paste the exact
header/footer markup from `partials/` between the same `jx:header` / `jx:footer` markers and add
`<link rel="stylesheet" href="/assets/chrome.css">` to `<head>`. `chrome.css` sets every property it
relies on (font, colors, margins, borders, focus outline) inside `.jx-header` / `.jx-footer`, because
hosts ship Tailwind preflight, global element rules or inline body fonts. Keep it that way: no global
selectors, no `:root` variables, no `position: fixed`.

If you change `partials/`, update the project repos to the same markup.

The footer has no newsletter signup. The Substack embed appears only on the homepage and /newsletter,
as `<div class="jx-embed-frame"><iframe class="jx-embed" ...></iframe></div>` in the page content. The
frame (border, panel, radius) is unfiltered site chrome; the iframe is inverted inside it, because
Substack serves that embed light and only follows the publication's own theme (`assets/chrome.css`).

## Verify before committing

```bash
python3 tools/build.py && git diff --exit-code       # idempotent, nothing left unbuilt
python -m pytest tests/                               # needs pytest
python3 tools/check_site.py                           # OG/Twitter/canonical, internal links, OG image size
python3 -m http.server 8000 &                         # serve the repo root (pages use root-relative URLs)
python tools/shots.py http://localhost:8000 /tmp/shots  # needs Playwright: overflow at 390/1280 + screenshots
```

`tools/og.py`, `tools/shots.py` and `tools/measure_embed.py` need Playwright with Chromium.
Lint: `uvx ruff check --line-length 120 tools tests`.
